Este es el mapa conceptual estático de las rutinas del agente de Python migradas desde n8n.

1. Inicialización (nodo_inicializar) Inicio

Nodos n8n originales: Normalizar, BD Analiza Intencion (Lectura de base de datos)

Parámetros de Entrada (Input State):

  • phone_number: Identificador del cliente.
  • msg_Categoria: Categorías de intención detectadas por el analizador SQL/LLM.

Parámetros de Salida (Output State):

  • sesion_slots: Datos actuales de sesión leídos de Postgres.
  • message_count: Cantidad de mensajes históricos del cliente.
  • categorias_pendientes: Cola ordenada de categorías a procesar.

Lógica: Carga el estado inicial de la sesión, lee el historial de chat e inicializa la cola de prioridades ordenando las categorías detectadas: SALUDO > DISPONIBILIDAD > PRECIOS > INFORMACION > SIN_CATEGORIA.

2. Saludo (nodo_saludo) Saludo

Nodos n8n originales: Condición Mensajes Previos, Genera Saludo

Parámetros de Entrada (Input State):

  • message_count: Número de mensajes históricos.
  • categorias_pendientes: Cola de procesamiento.

Parámetros de Salida (Output State):

  • respuestas: Añade el saludo correspondiente.
  • categorias_pendientes: Se remueve "SALUDO".
  • terminar_inmediatamente: true si solo se pedía un saludo.

Lógica: Si es el primer mensaje del cliente, le da la bienvenida formal ("Soy Teffy..."). Si ya ha interactuado antes, le da una bienvenida más directa ("Hola, ¿cómo podemos ayudarte?").

3. Disponibilidad (nodo_disponibilidad) Calendar

Nodos n8n originales: Google Calendar (Verificación de fecha y estado de reserva)

Parámetros de Entrada (Input State):

  • msg_FechaISO: Fecha extraída del mensaje de usuario actual.
  • sesion_slots: Valores acumulados de sesión (como Sesion_FechaISO y Sesion_Disponibilidad_Fecha).

Parámetros de Salida (Output State):

  • respuestas: Texto indicando disponibilidad.
  • sesion_slots: Guarda el nuevo estado de disponibilidad en la sesión de base de datos.
  • categorias_pendientes: Remueve "DISPONIBILIDAD".
  • terminar_inmediatamente: true si falta la fecha (Slot Filling).

Lógica: Si no hay fecha en el mensaje ni en la sesión, activa el Slot Filling para pedirla. Si hay fecha, consulta Google Calendar. Si la fecha ya estaba ocupada y el usuario vuelve a preguntar sin cambiar la fecha, le recuerda el estado para evitar re-consultas innecesarias.

4. Cotizador (nodo_precios) Cotizador

Nodos n8n originales: Postgres - fnObtienePrecio, Genera Mensaje Cotización

Parámetros de Entrada (Input State):

  • msg_FechaISO, msg_Ambiente, msg_Invitados.
  • sesion_slots (con slots acumulados de fecha, ambiente e invitados).

Parámetros de Salida (Output State):

  • respuestas: Agrega el precio referencial calculado.
  • terminar_inmediatamente: true si falta algún parámetro requerido.

Lógica: Si no hay disponibilidad, cancela el cálculo. Si está disponible, revisa si cuenta con Fecha, Ambiente e Invitados. Si falta alguno, realiza Slot Filling. Si tiene todos, invoca la función Postgres y formatea la cotización (ej: S/. 4.500).

5. Preguntas / RAG (nodo_informacion) RAG

Nodos n8n originales: Vector Store RAG, OpenAI GPT RAG

Parámetros de Entrada (Input State):

  • msg_Consulta: El texto original ingresado por el usuario.

Parámetros de Salida (Output State):

  • respuestas: Respuesta sintetizada basada en contexto local.

Lógica: Recupera los 12 fragmentos semánticos más relevantes de la base de datos de vectores (PGVector). Luego inyecta el prompt personalizado de prompt_rag.txt y llama a gpt-4o-mini para sintetizar de forma clara y reducida.

6. Fallas (nodo_sin_categoria) Fallback

Nodos n8n originales: Control de Fallas Consecutivas

Parámetros de Entrada (Input State):

  • msg_Sin_Categoria: Contador de fallos acumulado en la sesión de base de datos.

Lógica: Si no se entendió la consulta, responde pidiendo reformular. Si el contador de fallos es superior a 2, ofrece adicionalmente escribir la palabra "ASESOR" para poder pasar a un humano.

7. Compilación (nodo_compilar) Fin

Nodos n8n originales: Unificar Respuestas, Guardar Historial de Chat

Parámetros de Entrada (Input State):

  • respuestas: Colección de respuestas de los nodos visitados.
  • phone_number, msg_Consulta.

Lógica: Consolida las respuestas con saltos de línea dobles. Si excede el límite de 400 caracteres, realiza un resumen inteligente con GPT-4o-mini respetando los precios y fechas. Guarda la pregunta y la respuesta compilada en la tabla n8n_chat_histories para mantener la consistencia histórica.
